## 补充范围

本次在不修改 `source.md`、不改变原有七章顺序的前提下，扩写了：

- 01：K8s 的问题空间、声明式控制环、适用边界。
- 02：Cluster、Node、Namespace、Pod、Deployment、Service 关系；标签选择器数据流。
- 03：能力的“输入 → 动作 → 观察 → 边界”；ConfigMap、Secret 的使用与安全边界。
- 04：从环境确认到 apply、观察、更新、排查、清理的实践闭环。
- 05：`kubectl` 与 kind/minikube 的职责边界和选择规则。
- 06：按前提、概念、对象、部署、更新、排查、清理组织的学习路径。
- 07：源材料与官方资料证据、审查和验证记录。

## 已验证项

- 七个原有课程文件仍存在，顺序和文件名未变；新增本复盘作为闭环附录。
- `source.md` 未改动；其 SHA-256 与扩写前记录一致，见 [验证记录](07-verification-record.md#根源文件)。
- 所有 `Source-derived` 断言均保留 `SRC-*` 来源映射；研究扩展均使用 `RSC-*` 映射到 Kubernetes 官方页面。
- 所有章节均包含学习目标、具体例子或练习、相邻章节导航。
- 练习链覆盖：环境确认 → YAML → apply → get → rollout status → describe/logs → delete。
- 安全边界已明确：仅在授权集群执行；ConfigMap 不用于机密；Secret 需要加密与最小权限。

## 限制与遗留项

- 没有真实、已授权 Kubernetes 集群，因此未执行 YAML、`kubectl` 命令或收集运行输出。课程提供的是官方命令语义和预期观察，不是本仓库实测。
- 课程定位为入门，未覆盖 Ingress、持久卷、NetworkPolicy、RBAC 实作、生产可观测性、多集群或 GitOps。
- Kubernetes 文档随版本演进；使用课程前应以链接的官方页面和目标集群版本为准。

## 根因与预防

### 发现：原课程结构正确但教学密度不足

**根因：** 课程严格限于单一简介材料，拆分后只能形成准确提纲；安装前提、对象间运行链路、可观察验收和工具边界均缺少支持。

**已采取预防（AFK）：** 对缺口补充官方文档来源；将研究结论与原始结论分开标注；对每个实践步骤写出前提、动作、观察和清理。

**验收标准：** 读者可从第 06 章反向追到任一命令的对象定义、操作依据、预期观察与清理动作。

### 发现：实践教程容易伪造环境验证

**根因：** 文档示例常把命令和典型结果相邻展示，容易把“官方语义”误写成“本次已实测”。

**已采取预防（AFK）：** 明确区分“预期观察”和“实测输出”；在 04、06、07、08 章重复记录没有可执行集群。

**验收标准：** 文中没有声称本仓库已成功创建 Pod、Service 或完成 rollout。

## 最终结论

课程现在形成完整初学者闭环：先理解问题和声明式思维，再理解对象关系与能力边界，随后在受控环境中完成部署、观察、更新、排查和清理。证据分层清晰：原始材料用 `SRC-*`，官方补充用 `RSC-*`。运行时验证仍需读者在已授权练习集群执行；这不是文档缺口，而是外部环境边界。
